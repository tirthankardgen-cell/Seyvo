# 0.1.11 shortcut repair and Fn compatibility

Requested: make the bubble visible during Right Ctrl hold dictation, stop capture on release even if the key-up callback is missed, and retain Fn for keyboards that expose it. Both engineering briefs were read completely. The existing three-second start threshold, hold/toggle modes, native target checks, Google adapter and encrypted key format are preserved.

The old native listener depended entirely on key-up delivery. A 25 ms message-loop timer now checks only the assigned held key and can recover release, never generate activation. A real Windows regression removes the installed hook before release, confirms exactly one recovered up event and proves a later press without the hook cannot activate. Main also ignores rejected starts belonging to older gestures.

Previously the bubble was requested only after the three-second threshold and native target capture. It now displays Hold to start / Mic off during the gesture. Active status restores a shell-hidden window without activation; the bubble cannot minimize/maximize/fullscreen itself. Session startup waits for loading, and renderer loss stops capture. Regression tests hide and crash the actual Electron bubble and verify recovery, focus preservation, track teardown and the next session. This establishes tested failure paths, not a claim that every possible Windows compositor failure was reproduced from the user's report.

Fn is selectable. Its explicit, cancellable 12-second check requires two matching physical holds/releases (at least 300 ms each) and observed held state. Only non-typing F13–F24 or a narrow OEM event set is eligible; ordinary typing/modifiers and injected input cannot calibrate it. The main process validates and persists the mapping in `fn-key.json`; renderers receive only availability/checking flags. The same listener and main gesture handle calibrated Fn. Native work remains asynchronous, and lock/suspend/rebind/shutdown cancel probing.

No physical Fn-compatible keyboard has been validated for this version. Some keyboards expose no Fn event; arbitrary vendor HID protocols and injected software remaps are not supported. The Fn Electron scenario seeds a saved F13 mapping and uses Win32 SendInput: it proves the mapped execution path, not hardware calibration. The no-event test proves timeout/fallback and sleep cancellation with the microphone off. The user explicitly requested retaining this conditional support rather than removing Fn because of one laptop.

Windows 11 x64 host: HP Pavilion x360 14-ek0xxx. Node 26.13.0; committed npm lockfile. Core gate passed 79 tests, typecheck, lint and production/native build. Unit/provider tests use mocks except the identified real Windows process/key tests. Focused Electron tests passed Right Ctrl and the seeded Fn mapping with a loopback provider and synthetic microphone, including visibility, release in under one second, both modes, pause/resume and listener loss. Overlay crash/restart passed separately. A first affected test refused a changed desktop target; that run is not counted as a pass, and target refusal was not weakened.

Clean `npm ci` audited 496 installed packages with zero vulnerabilities. Source secret scan passed. Inventory/SBOM regenerated. The clean Electron run initially stalled fetching its runtime; the cached 45.2.3 Windows x64 archive was verified against official SHASUMS256.txt (`489cd061908e697394b004298bf5ffd345c935d10e8ca197ba819f019ab2dec0`) and used to restore that exact runtime before rerunning. The interrupted attempt is not a passing suite.

Security review: new IPC is one fixed dashboard action and two validated settings enums; no arbitrary native key or process command reaches renderers. Native calibration emits only a bounded validated mapping after explicit intent, never typed content. Shortcuts are suspended during calibration; dictation and local mic tests are refused. Existing sender validation, microphone authorization, safe insertion refusal, DPAPI storage and no-auto-submit remain. No dependencies, telemetry, services, drivers, cloud endpoints, transcript logs or audio persistence were introduced. Stable gates (signing, clean-machine and broader physical acceptance) remain open.

Installed, provider, packaging and hosted artifact observations will be appended after the candidate is built and checked. This is an unsigned validation prerelease, not a stable-release acceptance record.

The final local full Electron rerun passed all 14 scenarios. The final source core gate passed all 79 tests, typecheck, lint and production/native build. Fn timeout/cancellation, the mapped Fn execution path, and actual Right Ctrl delivery are distinct observations; physical Fn calibration remains unverified.
