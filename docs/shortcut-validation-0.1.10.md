# 0.1.10 shortcut validation

Scope: preserve the current combination by default; add Right Ctrl single-key hold/toggle, both with a three-second start. Fn has no standard Windows virtual key and is explicitly unavailable. No provider, clipboard algorithm, stored-key format or history behavior changes.

On the Windows 11 x64 development workstation, Node 26.13.0 and the committed npm lockfile: `npm run check` passed 73 tests, typecheck, lint and production/native build. The existing Electron suite was run, and affected shortcut scenarios were rerun after corrections. The single-key scenario passed actual Win32 SendInput delivery through the production native listener, short-press rejection, no microphone before three seconds, release-to-finish, release-and-tap toggle, exact insertion into the owned test field, paused holds, resuming with Ctrl already held, and native-helper loss with microphone teardown and combination fallback. The shortcut settings scenario passed mode persistence across restart and returning to the saved F6 combination. The existing consecutive-insertion scenario passed after explicitly reselecting its owned test field before Stop.

Unit/provider tests use mocks. These Electron shortcut tests use a loopback provider and synthetic microphone; Windows keyboard delivery and the native target are real. They do not prove physical key presses, real Google recognition or bare Fn support. Earlier failures included focus moving to ChatGPT on the shared desktop, an over-expanded test scenario, and incorrect process targeting in the helper-failure harness. Those attempts are not counted as passes. The final helper-failure test checks exactly one helper belonging to the actual Electron main PID and stops it from the external test runner.

Security review of this change: the renderer can select only validated activation/mode enums; it cannot supply virtual keys, arbitrary listeners or native commands. The native callback emits only fixed Right Ctrl edges/interruption markers, never typed text or other key identities. Normal Ctrl combinations are not swallowed. Events carry a generation, main owns the activation timer, active sessions retain normal target validation, and release during setup cancels rather than leaving a delayed microphone activation. Pause/sleep/lock/rebind/quit reset pending gestures. No new dependencies, credentials, transcript logging, audio persistence, services or network destinations were added. Dependency audit reported zero vulnerabilities; source secret scan and supply-chain generation passed. Existing unsigned/stable-release gates remain open.
